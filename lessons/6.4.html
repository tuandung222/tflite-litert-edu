Đối với các ứng dụng di động xử lý thời gian thực tốc độ cao như AR (Thực tế ảo tăng cường), bám vết khuôn mặt (Face Tracking), hoặc nhận diện cử chỉ 60 FPS, việc mất 5ms đến 10ms chỉ để sao chép mảng byte hình ảnh qua cầu nối JNI (Java Native Interface) là hoàn toàn không thể chấp nhận được. Nó làm cạn kiệt tài nguyên CPU và gây nóng máy nhanh chóng.

Để đạt được độ trễ tiệm cận 0ms cho bước tiền xử lý, các ML Engineer cấp cao sử dụng kỹ thuật Zero-Copy Execution (Thực thi không sao chép vùng nhớ) thông qua việc ràng buộc trực tiếp bộ nhớ phần cứng AHardwareBuffer vào nhân GPU Delegate của LiteRT.

1. Tại sao JNI sao chép bộ nhớ truyền thống gây thắt nút cổ chai?

Quy trình xử lý ảnh Camera truyền thống trên Android diễn ra như sau:

Camera Sensor → ImageReader (YUV) → Java Heap (Bitmap/ByteArray) → JNI Copy → Native C++ memory → GPU Upload → Inference

Có ít nhất 3 lần sao chép bộ nhớ (Memory Copy) xảy ra trên RAM vật lý. Ở độ phân giải Full HD (1920x1080), mỗi khung hình chiếm khoảng 6MB bộ nhớ thô. Ở tốc độ 30 FPS, CPU phải sao chép liên tục 180MB/giây qua lại giữa các phân vùng ảo. CPU bị quá tải vì phải di chuyển mảng byte liên tục, trong khi GPU nhàn rỗi chờ nạp dữ liệu.

2. Giải pháp Cứu cánh: Android AHardwareBuffer

Được giới thiệu từ Android Oreo (API 26), AHardwareBuffer là một đối tượng hệ thống đại diện cho một phân vùng bộ nhớ phần cứng thô (Hardware-backed buffer).

Điểm đặc biệt của `AHardwareBuffer` là nó có thể được **truy cập đồng thời** bởi nhiều phần cứng khác nhau mà không cần sao chép:

  • Camera Sensor: Ghi trực tiếp khung hình thô vào buffer phần cứng.
  • GPU (OpenGL/Vulkan): Coi buffer này như một GPU Texture để thực hiện render hoặc tiền xử lý (Scale, Crop, Normalize) cực nhanh bằng Compute Shader.
  • LiteRT GPU Delegate: Đọc trực tiếp dữ liệu từ chính phân vùng bộ nhớ này làm Tensor đầu vào.
Camera Sensor → [ AHardwareBuffer (Shared Memory) ] → GPU Delegate Inference
                                 ↑
                         GPU Shader Preprocessing (Zero-Copy)

3. Triển khai Mã nguồn Native JNI Zero-Copy trong C++

Dưới đây là mã nguồn C++ JNI cấp độ sản xuất hướng dẫn cách ánh xạ trực tiếp một đối tượng AHardwareBuffer của hệ thống Android vào Tensor đầu vào của LiteRT Interpreter:

#include 
#include 
#include "tensorflow/lite/core/c/common.h"
#include "tensorflow/lite/interpreter.h"
#include "tensorflow/lite/delegates/gpu/delegate.h"

extern "C"
JNIEXPORT jboolean JNICALL
Java_com_example_litert_ZeroCopyManager_bindHardwareBuffer(
    JNIEnv* env, jobject thiz,
    jlong interpreter_addr, // Địa chỉ native của Interpreter
    jobject hardware_buffer_obj, // Đối tượng AHardwareBuffer từ Java
    jint tensor_index // Chỉ số tensor đầu vào (ví dụ: 0)
) {
    // 1. Lấy con trỏ Interpreter từ Java Address truyền xuống
    tflite::Interpreter* interpreter = reinterpret_cast(interpreter_addr);
    if (!interpreter) return JNI_FALSE;

    // 2. Chuyển đổi Java HardwareBuffer sang đối tượng Native AHardwareBuffer
    AHardwareBuffer* hardware_buffer = AHardwareBuffer_fromHardwareBuffer(env, hardware_buffer_obj);
    if (!hardware_buffer) return JNI_FALSE;

    // 3. Đọc thông tin mô tả của buffer phần cứng
    AHardwareBuffer_Desc desc;
    AHardwareBuffer_describe(hardware_buffer, &desc);
    
    // Đảm bảo kiểu định dạng buffer là GPU Texture hoặc Shared Memory
    if (!(desc.usage & AHARDWAREBUFFER_USAGE_GPU_SAMPLED_IMAGE)) {
        return JNI_FALSE; // Buffer không được cấu hình cho GPU đọc trực tiếp
    }

    // 4. RÀNG BUỘC KHÔNG SAO CHÉP (Zero-Copy Bind)
    // Thay vì gọi interpreter->CopyToBuffer(), ta bind trực tiếp địa chỉ vật lý
    TfLiteStatus status = interpreter->BindBufferToTensor(
        tensor_index, 
        kTfLiteHardwareBufferAndroid, // Định danh kiểu buffer Android đặc biệt
        hardware_buffer, 
        desc.width * desc.height * 4 // Kích thước byte thực tế
    );

    if (status != kTfLiteOk) {
        return JNI_FALSE; // Ràng buộc thất bại
    }

    // Tăng biến tham chiếu để Android OS không tự động giải phóng vùng nhớ buffer khi đang inference
    AHardwareBuffer_acquire(hardware_buffer);
    return JNI_TRUE;
}

4. Cấu hình phía Kotlin trên Android Studio

Tại mã nguồn ứng dụng Java/Kotlin, ta khởi tạo HardwareBuffer thông qua luồng output của CameraX hoặc bộ giải mã đồ họa ImageReader:

import android.hardware.HardwareBuffer
import android.media.ImageReader

class ZeroCopyAndroidPipeline {

    private var interpreterAddress: Long = 0 // Địa chỉ JNI khởi tạo từ trước
    private var zeroCopyManager = ZeroCopyManager()

    fun setupCameraPipeline(width: Int, height: Int) {
        // Khởi tạo ImageReader hỗ trợ GPU usage để tạo AHardwareBuffer
        val imageReader = ImageReader.newInstance(
            width, height, 
            android.graphics.ImageFormat.PRIVATE, 2,
            HardwareBuffer.USAGE_GPU_SAMPLED_IMAGE or HardwareBuffer.USAGE_GPU_COLOR_OUTPUT
        )

        imageReader.setOnImageAvailableListener({ reader ->
            val image = reader.acquireLatestImage()
            if (image != null) {
                // Lấy đối tượng HardwareBuffer phần cứng từ Frame
                val hardwareBuffer: HardwareBuffer? = image.hardwareBuffer
                
                if (hardwareBuffer != null) {
                    // Ánh xạ trực tiếp không sao chép byte sang Native C++
                    val success = zeroCopyManager.bindHardwareBuffer(
                        interpreterAddress, 
                        hardwareBuffer, 
                        0 // Input Tensor Index 0
                    )
                    
                    if (success) {
                        // Kích hoạt chạy Inference thô cực nhanh trực tiếp trên GPU VRAM!
                        zeroCopyManager.runInference(interpreterAddress)
                    }
                    
                    hardwareBuffer.close()
                }
                image.close()
            }
        }, null)
    }
}
